# 10 - Permissions, Securite et Audit

توثق هذه الوثيقة الصلاحيات، الحماية، وسجل التعديلات.

## الأدوار

| الدور | الوصف |
| --- | --- |
| Admin | صلاحيات كاملة |
| Direction | قراءة التقارير والبيلان واعتماد بعض العمليات |
| Comptable | إدخال ومراجعة المحاسبة |

## قواعد أمنية

- كل مستخدم له حساب خاص.
- لا يسمح بحسابات مشتركة.
- كلمات المرور تخزن hashed.
- يمكن تعطيل المستخدم دون حذف سجله.
- كل عملية حساسة تحفظ في audit log.

## العمليات الحساسة

يجب تسجيلها:

- إنشاء أو تعديل أو حذف عملية مالية.
- تغيير مبلغ.
- اعتماد الرواتب.
- غلق شهر.
- فتح شهر مغلق.
- تعديل موظف أو عقد.
- حذف ملف مرفق.
- تغيير صلاحيات مستخدم.

## Audit Log

كل سجل يحتوي:

- user_id
- action
- entity_type
- entity_id
- old_values
- new_values
- reason
- created_at

## أسباب التعديل

عند تعديل سجل مالي بعد الحفظ، يطلب النظام سبب:

- Erreur de saisie
- Correction montant
- Annulation paiement
- Changement mode paiement
- Regularisation
- Autre

## سياسة الشهر المغلق

الشهر المغلق:

- قراءة فقط لكل المستخدمين العاديين.
- الطباعة والتصدير مسموحة.
- التعديل الاستثنائي يحتاج Admin.
- كل تعديل بعد الغلق يحمل سبب واضح.
- بعد التعديل يجب إعادة حساب monthly balance.

## حماية البيانات

تتطلب حماية البيانات وجود:

- نسخ احتياطي يومي.
- نسخ احتياطي قبل غلق الشهر.
- حفظ المرفقات في مجلد منظم أو storage خاص.
- منع حذف audit log.

## الخصوصية

بيانات الموظفين والرواتب حساسة:

- لا تظهر الرواتب للمستخدمين غير المصرح لهم.
- Viewer لا يرى تفاصيل الهواتف والوثائق إذا لم يكن مصرحا.
- تصدير salaires وDRH يسجل دائما في audit log.
